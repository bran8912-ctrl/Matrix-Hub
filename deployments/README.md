# Deployments

This directory contains deployment information for Matrix-Hub smart contracts on various Ethereum networks.

## Purpose

The deployment JSON files in this directory are used by the frontend (Astro) to:
- Access deployed contract addresses
- Display deployment metadata
- Configure web3 integrations
- Interact with smart contracts

## Files

### `mtx-<network>.json`
Contains deployment information for the MTX (Matrix-HubCoin) ERC-20 token.

**Example:**
```json
{
  "network": "sepolia",
  "contractAddress": "0x...",
  "deployer": "0x...",
  "deploymentTime": "2026-01-06T23:32:00.000Z"
}
```

### `casino-<network>.json`
Contains deployment information for all casino-related contracts.

**Example:**
```json
{
  "network": "sepolia",
  "chainId": 11155111,
  "deployer": "0x...",
  "deploymentTime": "2026-01-06T23:32:00.000Z",
  "contracts": {
    "mtxToken": "0x...",
    "casinoCore": "0x...",
    "casinoReserve": "0x...",
    "liquidityRouter": "0x...",
    "rngEngine": "0x..."
  },
  "parameters": {
    "reserveCap": "1000000000000000000000000",
    "minBet": "1000000000000000000",
    "maxBet": "1000000000000000000000"
  }
}
```

## Networks

Deployment files are network-specific:
- `*-sepolia.json` - Sepolia testnet deployments
- `*-mainnet.json` - Ethereum mainnet deployments
- `*-localhost.json` - Local development deployments (not committed)

## Usage in Frontend

### Importing Deployment Data

```typescript
// In Astro components or TypeScript files
import casinoDeployment from '../../deployments/casino-sepolia.json';

const casinoCoreAddress = casinoDeployment.contracts.casinoCore;
```

### Dynamic Network Selection

```typescript
const network = import.meta.env.PUBLIC_NETWORK || 'sepolia';
const deployment = await import(`../../deployments/casino-${network}.json`);
```

### With ethers.js

```typescript
import { ethers } from 'ethers';
import casinoDeployment from '../../deployments/casino-sepolia.json';
import CasinoCoreABI from '../abi/CasinoCore.json';

const provider = new ethers.BrowserProvider(window.ethereum);
const casinoCore = new ethers.Contract(
  casinoDeployment.contracts.casinoCore,
  CasinoCoreABI,
  provider
);
```

## Generating Deployment Files

Deployment files are automatically generated by deployment scripts:

```bash
# Deploy MTX token
npx hardhat run scripts/deploy_mtx.js --network sepolia

# Deploy casino contracts
npx hardhat run scripts/deploy_casino.js --network sepolia
```

## Version Control

These files **ARE tracked in git** to ensure:
- Frontend can import contract addresses
- Deployment history is preserved
- Team members have consistent contract addresses
- CI/CD can access deployment information

**All deployment files are committed** including:
- ✅ Testnet deployments (sepolia)
- ✅ Mainnet deployments
- ✅ Localhost deployments (for development reference)

This ensures the entire team has access to all deployment information across all networks.

## Security Considerations

Deployment files contain:
- ✅ Contract addresses (public on blockchain)
- ✅ Network information (public)
- ✅ Deployment timestamps (public)
- ❌ NO private keys
- ❌ NO secrets
- ❌ NO sensitive data

These files are safe to commit to public repositories.

## Updating Deployments

When redeploying contracts:
1. Run the deployment script for the network
2. The script will overwrite the existing deployment file
3. Review the changes with `git diff deployments/`
4. Commit the updated deployment file
5. Update frontend code if contract addresses changed

## Troubleshooting

### File Not Found
If importing fails, ensure:
- The deployment script has been run for that network
- The JSON file exists in this directory
- The import path is correct relative to your file

### Wrong Network
If contract addresses don't work:
- Verify you're using the correct network file
- Check your wallet is connected to the matching network
- Confirm the contracts are deployed on that network

### Stale Addresses
If contracts don't respond:
- Check if contracts have been redeployed
- Update deployment files with latest addresses
- Clear browser cache and rebuild frontend
